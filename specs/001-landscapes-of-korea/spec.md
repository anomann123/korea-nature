# Feature Specification: 한국의 결 (Landscapes of Korea)

**Feature Branch**: `001-landscapes-of-korea`

**Created**: 2026-09-12

**Status**: Draft

**Input**: User description: "'한국의 결'이라는 제목의 단일 페이지 문화관광 웹사이트. 설악산·제주·순천만·보성 녹차밭 네 장소를 큰 사진, 충분한 한국어 본문, 연속적인 스크롤 경험으로 소개하는 편집형 사이트. 실제 라이선스가 확인된 사진을 직접 확보하여 사용."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 스크롤로 네 곳의 풍경을 순서대로 감상한다 (Priority: P1)

방문자가 사이트에 들어와 Hero를 보고, 아래로 스크롤하며 설악산 → 제주 → 순천만 → 보성 녹차밭 순서로 각 장소의 대표 사진과 소개 글을 하나의 연속된 흐름으로 만난 뒤, 마지막 CTA와 footer에 도달한다.

**Why this priority**: 이것이 사이트의 유일한 목적이자 전체 경험이다. 이 흐름이 성립하지 않으면 사이트 자체가 성립하지 않는다.

**Independent Test**: 페이지 최상단에서 최하단까지 스크롤만으로 이동해, 6개 구획(Hero, 설악산, 제주, 순천만, 보성 녹차밭, CTA/footer)이 이 순서대로 모두 나타나는지 확인하는 것으로 완전히 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 방문자가 페이지 최상단(Hero)에 있을 때, **When** 아래로 스크롤하면, **Then** 다음 구획(설악산)의 이미지와 본문이 이전 구획과 짧게 겹쳐 보인 뒤 자연스럽게 전환되어 나타난다.
2. **Given** 방문자가 임의의 장소 구획을 읽고 있을 때, **When** 스크롤을 멈추면, **Then** 그 구획의 이미지와 본문이 화면에 계속 유지되어 전환이 저절로 이어지거나 중간에 사라지지 않는다.
3. **Given** 방문자가 보성 녹차밭 구획을 지나쳤을 때, **When** 계속 스크롤하면, **Then** 마지막 CTA 문구와 버튼, footer가 순서대로 나타난다.

---

### User Story 2 - 각 장소의 본문을 방해받지 않고 읽는다 (Priority: P2)

방문자가 특정 장소(예: 순천만) 구획에 머무르며 두 개의 본문 문단과 키워드를 여유 있게 읽는다. 본문은 사진 위의 작은 캡션이 아니라 읽기 좋은 크기·행간을 가진 별도의 읽기 영역(나란히 배치 또는 반투명 패널)에 놓여 있다.

**Why this priority**: 사이트의 목적은 "사진 감상과 글 읽기가 어느 한쪽에 치우치지 않는 것"이므로, 본문이 실제로 읽히지 않으면 핵심 가치가 무너진다. 스크롤 연출(P1)이 성립해도 글을 읽을 수 없으면 실패다.

**Independent Test**: 아무 장소 구획에서나 스크롤을 멈추고, 본문 두 문단과 키워드가 전부 화면에 남아 있는 상태로 끝까지 읽을 수 있는지, 데스크톱에서 본문 폭이 대략 36~48rem 범위에 들어오는지 확인하는 것으로 검증한다.

**Acceptance Scenarios**:

1. **Given** 데스크톱 화면에서 임의의 장소 구획을 보고 있을 때, **When** 본문 영역을 측정하면, **Then** 본문 폭이 약 36~48rem 범위 안에 있고 문단 사이 행간이 촘촘한 캡션 수준이 아니라 읽기용 문단 수준이다.
2. **Given** 방문자가 한 장소 구획에서 스크롤을 멈췄을 때, **When** 몇 초간 움직이지 않으면, **Then** 본문이 나타난 직후 곧바로 사라지지 않고 읽는 동안 유지된다.
3. **Given** 모바일 화면에서 같은 장소 구획을 볼 때, **When** 세로로 스크롤하면, **Then** 동일한 본문 두 문단과 키워드가 축약되거나 숨겨지지 않고 그대로 노출된다.

---

### User Story 3 - 네 장소가 서로 다른 리듬으로 구성되어 있음을 느낀다 (Priority: P3)

방문자가 설악산에서 보성 녹차밭까지 차례로 넘어가면서, 각 장소 구획마다 이미지·본문의 좌우 배치, 정렬, 여백이 조금씩 달라 "여행 잡지를 넘기는" 듯한 인상을 받는다.

**Why this priority**: 콘텐츠와 스크롤 흐름(P1, P2)이 이미 성립한 뒤에 더해지는 편집 디자인 품질 요소로, 없어도 사이트는 기능하지만 있으면 목적한 "편집형 문화관광 사이트"라는 느낌이 완성된다.

**Independent Test**: 네 장소 구획을 나란히 비교해, 이미지-본문의 좌우 위치·정렬·여백이 모든 구획에서 동일하게 반복되지 않고 구획마다 뚜렷이 구별되는지 확인하는 것으로 검증한다.

**Acceptance Scenarios**:

1. **Given** 네 장소 구획을 순서대로 훑어볼 때, **When** 각 구획의 레이아웃을 비교하면, **Then** 최소 두 가지 이상의 서로 다른 좌우 배치/정렬 패턴이 사용되어 동일한 배치가 네 곳 모두에 반복되지 않는다.

---

### Edge Cases

- `prefers-reduced-motion`을 활성화한 방문자가 스크롤할 때: 확대·교차·시차 등장 애니메이션이 최소화되되, 각 장소의 이미지와 본문 콘텐츠는 동일하게 모두 노출되어야 한다.
- 키보드만으로 탐색하는 방문자가 Tab/화살표/Page Down 등으로 이동할 때: 스크롤 잠금이나 섹션별 강제 정지 없이 자연스러운 문서 흐름으로 이동할 수 있어야 한다.
- 뷰포트가 매우 낮은 기기(짧은 세로 높이의 모바일, 폴더블 등)에서: 이미지가 화면을 다 채우지 못해도 본문이 잘리거나 겹쳐 보이지 않아야 한다.
- 이미지 로딩이 느린 환경에서: 대표 사진이 아직 로드되지 않은 구획도 레이아웃이 무너지거나(레이아웃 시프트) 본문이 사라지지 않아야 한다.
- 설악산·제주·순천만·보성 녹차밭 중 어느 한 곳이라도 재사용 조건이 확인된 사진을 확보하지 못한 경우: 해당 장소를 placeholder나 단색 박스로 대체하지 않고, 어떤 장소의 사진이 누락되었는지 명확히 알리며 구현을 미완료 상태로 남겨야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사이트는 Hero, 설악산, 제주, 순천만, 보성 녹차밭, 마지막 CTA/footer 순서의 단일 페이지 6개 구획으로 구성되어야 한다.
- **FR-002**: Hero 구획은 제목("한국의 결"), 영문 표기("LANDSCAPES OF KOREA"), 그리고 페이지의 관점을 설명하는 리드문 전체 텍스트를 포함해야 한다.
- **FR-003**: 각 장소 구획은 장소의 한국어 이름과 영문 이름, 풍경의 성격을 짚는 한 줄 제목, 서로 다른 길이의 본문 두 문단, 2~3개의 짧은 풍경 키워드, 전체 화면에 가까운 대표 사진을 모두 포함해야 한다.
- **FR-004**: 각 장소의 본문 두 문단은 사용자가 제공한 지정된 한국어 문구를 축약·요약하지 않고 그대로 사용해야 한다.
- **FR-005**: 본문은 사진 위에 얹힌 작은 캡션 형태로 축소되지 않고, 데스크톱에서 독립된 읽기 영역(이미지와 나란히 배치되거나 반투명 읽기 패널)에 배치되어야 한다.
- **FR-006**: 데스크톱 화면에서 본문 영역의 폭은 약 36~48rem 범위를 유지해야 하며, 충분한 행간을 가져야 한다.
- **FR-007**: 네 장소 구획은 이미지·본문의 좌우 위치, 정렬, 여백 중 최소 한 가지 이상을 서로 다르게 구성하여 동일한 배치가 반복되지 않아야 한다.
- **FR-008**: 스크롤 시 장면 전환은 다음 이미지가 서서히 확대되며 등장하고 이전 이미지와 짧게 겹친 뒤 교차하는 방식으로 구현되어야 하며, 장소 이름·한 줄 제목·본문은 서로 시차를 두고 순차적으로 등장해야 한다.
- **FR-009**: 스크롤 경험은 섹션별 스크롤 고정(pin) 후 반복적으로 멈췄다 풀리는 방식, CSS `scroll-snap`, 휠 이벤트 가로채기, 강제 스크롤 이동, 한 번의 휠 동작으로 장면 전체가 교체되는 전환을 사용하지 않아야 한다.
- **FR-010**: 각 장소 구획에서 본문을 읽을 수 있는 시간(스크롤이 멈춰 있거나 느리게 진행되는 구간)이 충분히 유지되어야 하며, 콘텐츠가 나타나자마자 사라지지 않아야 한다.
- **FR-011**: 모바일 화면에서는 본문 두 문단과 키워드를 한두 줄로 줄이거나 숨기지 않고 동일하게 전체 노출해야 한다.
- **FR-012**: `prefers-reduced-motion`을 요청하는 사용자에게는 확대·교차·시차 등장 애니메이션을 최소화한 상태로 동일한 콘텐츠를 제공해야 한다.
- **FR-013**: 모든 인터랙티브 요소(마지막 CTA 버튼 등)는 키보드만으로 접근하고 실행할 수 있어야 하며, 페이지는 semantic HTML 구조를 사용해야 한다.
- **FR-014**: 마지막 CTA 구획은 지정된 제목·문장·버튼 문구를 포함하고, 버튼은 페이지 최상단(Hero)으로 되돌아가는 동작을 수행해야 한다.
- **FR-015**: 사이트는 설악산, 제주, 순천만, 보성 녹차밭 각각에 대해 재사용 조건이 확인된 실제 사진(각 장소 최소 1장, 상세 페이지에서 출처·작가·라이선스 확인 가능)과 Hero용 한국 자연 풍경 사진 1장을 확보하여 사용해야 하며, placeholder 이미지·단색 박스·외부 이미지 hotlink를 최종 결과에 남기지 않아야 한다.
- **FR-016**: 사용된 모든 이미지는 프로젝트 내 파일 경로, 촬영자 또는 제공 기관, 원본 상세 페이지 URL, 라이선스/사용 조건, 확인 날짜를 `CREDITS.md`에 기록해야 한다.
- **FR-017**: 모든 이미지에는 풍경을 구체적으로 설명하는 한국어 대체 텍스트(alt)를 제공해야 한다.
- **FR-018**: 설악산, 제주, 순천만, 보성 녹차밭 중 재사용 조건이 확인된 실제 사진을 확보하지 못한 장소가 있는 경우, 해당 사실을 명확히 보고하고 그 장소를 placeholder로 대체한 상태를 구현 완료로 간주하지 않아야 한다.
- **FR-019**: 모든 페이지 경로와 이미지 경로는 상대 경로로 구성되어 GitHub Project Pages의 하위 경로에서도 정상 동작해야 한다.

### Key Entities

- **장소 구획(Place Section)**: 설악산·제주·순천만·보성 녹차밭 각각을 나타내는 콘텐츠 단위. 한국어/영문 이름, 한 줄 제목, 본문 두 문단, 키워드 목록, 대표 이미지 참조, 레이아웃 변형(이미지-본문 좌우 배치) 속성을 가진다.
- **이미지 자산(Image Asset)**: `assets/images` 아래 저장되는 다운로드된 사진 파일. 파일 경로, 연결된 장소 구획, 한국어 alt 텍스트, 출처 크레딧(작가/기관, 원본 URL, 라이선스, 확인 날짜)과 연결된다.
- **크레딧 항목(Credit Entry)**: `CREDITS.md`에 기록되는 이미지별 출처 레코드. 파일 경로, 작가/제공 기관, 원본 URL, 라이선스, 확인 날짜로 구성된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 방문자는 별도의 클릭이나 메뉴 탐색 없이 스크롤 동작만으로 Hero부터 footer까지 6개 구획을 모두 경험할 수 있다.
- **SC-002**: 임의의 장소 구획에서 스크롤을 멈췄을 때, 해당 장소의 본문 두 문단 전체를 화면 안에서 끝까지 읽을 수 있는 시간이 유지된다(콘텐츠가 등장 직후 곧바로 사라지지 않는다).
- **SC-003**: 네 장소 구획을 비교했을 때 이미지-본문 배치, 정렬, 여백 패턴이 모두 동일하게 반복되지 않고 최소 2가지 이상의 구별되는 구성이 관찰된다.
- **SC-004**: `prefers-reduced-motion`을 켠 상태로 페이지 전체를 스크롤했을 때, 과도한 확대·교차 애니메이션 없이도 모든 구획의 이미지와 본문 콘텐츠를 빠짐없이 확인할 수 있다.
- **SC-005**: 모바일 화면 폭에서 각 장소 구획의 본문 두 문단과 키워드가 데스크톱과 동일하게 전체 노출되어, 축약되거나 가려진 텍스트가 없다.
- **SC-006**: 사용된 모든 이미지(Hero 포함 5장 이상)에 대해 `CREDITS.md`에서 파일 경로·출처·원본 URL·라이선스·확인 날짜를 100% 확인할 수 있다.
- **SC-007**: 키보드만으로 페이지 최상단부터 CTA 버튼까지 도달하고 버튼을 실행할 수 있다.
- **SC-008**: GitHub Project Pages의 하위 경로(예: `username.github.io/repo/`)에 배포했을 때 모든 페이지 요소와 이미지가 깨짐 없이 로드된다.

## Assumptions

- Hero, 네 장소, CTA에 사용되는 모든 한국어 문구는 사용자가 제공한 원문 그대로 사용하며 별도의 번역이나 축약 없이 반영한다는 가정 하에 작성되었다.
- "재사용 조건을 확인할 수 있는 사진"은 Wikimedia Commons, Unsplash, Pexels 등 원문 상세 페이지에서 라이선스와 작가를 확인할 수 있는 출처를 의미하며, 출처 불명 이미지나 디자인 레퍼런스 사이트(KIKO, Framer 등)의 자산은 후보에서 제외한다는 가정을 따른다.
- 스크롤 연출은 "섹션별 강제 pin 및 scroll-snap 금지"라는 제약 안에서, 스크롤 위치에 따라 요소의 투명도·크기·위치를 연속적으로 변화시키는 방식(예: 스크롤 진행률 기반 트랜지션)으로 구현한다고 가정한다. 구체적인 구현 기술은 계획(plan) 단계에서 결정한다.
- 사이트는 로그인, 서버, 데이터베이스가 없는 정적 페이지이며(프로젝트 헌법과 일치), 이미지 확보 과정에서의 네트워크 접근을 제외하면 최종 산출물은 순수 정적 파일로 구성된다는 가정을 따른다.
- 최종 CTA 버튼의 동작은 "처음 풍경부터 다시 보기"라는 문구에 따라 페이지 최상단(Hero)으로 스크롤 이동하는 것으로 가정한다.
